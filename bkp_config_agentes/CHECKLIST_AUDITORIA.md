# Checklist de auditoria e encerramento

## Antes de iniciar

- [ ] Issue e comentários lidos.
- [ ] `AGENTS.md` canônico e instruções do agente lidos.
- [ ] Estudo/requisito existente consultado.
- [ ] Escopo e critérios de aceite explícitos.
- [ ] Riscos, dependências e necessidade de aprovação identificados.

## Durante a execução

- [ ] Alterações limitadas ao escopo.
- [ ] Nenhum segredo foi adicionado a logs, commits ou Markdown.
- [ ] Mudanças destrutivas foram evitadas ou aprovadas.
- [ ] Progresso registrado na issue.
- [ ] Falhas e desvios documentados.

## Antes de encerrar

- [ ] Diff revisado.
- [ ] Testes relevantes executados.
- [ ] Resultado real descrito (não presumido).
- [ ] Evidência associada à issue.
- [ ] Documentação e histórico atualizados.
- [ ] Pendências e responsável definidos.
- [ ] Status do board coerente.
- [ ] Revisão/aceite real obtido quando exigido.

## Aprovações humanas

Exigir aprovação conforme política do projeto para deploy, alteração de secrets, migrações destrutivas, reset de banco, operações irreversíveis e ações Git protegidas.
